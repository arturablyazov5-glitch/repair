# Заявки с сайта и аналитика — инструкция для владельца

Как это работает: человек заполняет форму на сайте → сайт отправляет заявку на небольшой «приёмник» (сервер) → приёмник проверяет её и присылает сообщение в Telegram. Пока приёмник не настроен, форма открывает WhatsApp с готовым текстом (так сделано сейчас).

Есть два варианта приёмника, выберите один:

| | A. Cloudflare Worker (`server/worker.js`) | B. Свой сервер в РФ (`server/node-server.mjs`) |
|---|---|---|
| Где работает | Серверы Cloudflare (за рубежом) | Любой VPS/хостинг с Node.js в России |
| Цена | Бесплатно (100 000 запросов в день) | Стоимость VPS (от ~200–300 ₽/мес) |
| Настройка | 10 минут, без сервера | Нужен сервер, домен, nginx |
| 152-ФЗ | Данные обрабатываются за рубежом — см. раздел «152-ФЗ» | **Рекомендуется**: заявки сначала сохраняются в РФ |

---

## 1. Telegram-бот и chat id

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя (например, «Сервис-Люкс заявки») и логин бота (должен заканчиваться на `bot`).
2. BotFather пришлёт **токен** вида `123456789:AA...`. Это пароль от бота: никому не пересылайте, не вставляйте в код сайта и в репозиторий.
3. **Chat id для теста (личка):** напишите своему боту любое сообщение (`/start`). Затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе найдите `"chat":{"id":123456789` — это ваш chat id.
4. **Chat id рабочего чата:** создайте группу (например, «Заявки Сервис-Люкс»), добавьте туда бота и менеджеров, напишите в группе сообщение, снова откройте `getUpdates`. Id группы отрицательный: `-100…`.
   Если в ответе пусто — у бота включён «privacy mode»: напишите в группе команду `/start@логин_бота` или отключите privacy в BotFather (`/setprivacy` → Disable).
5. Пробная отправка (замените значения):
   `https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<CHAT_ID>&text=test` — сообщение должно прийти.

## 2. Переменные

| Переменная | Что это | Пример | Где хранить |
|---|---|---|---|
| `BOT_TOKEN` | токен бота от BotFather | `123456789:AA…` | **секрет** |
| `CHAT_ID` | куда слать заявки | `-1001234567890` | секрет (или переменная) |
| `ALLOWED_ORIGIN` | адрес сайта, с которого принимаем заявки (несколько — через запятую, без `/` в конце) | `https://servis-lux.ru,https://www.servis-lux.ru` | переменная |
| `LEADS_FILE` | *(только вариант B)* файл, куда дописывается каждая заявка | `/var/lib/servis-leads/leads.jsonl` | переменная |
| `PORT`, `HOST` | *(B)* порт и адрес; по умолчанию `8787`, `127.0.0.1` | | переменная |
| `TRUST_PROXY` | *(B)* `1`, если сервер стоит за вашим nginx (берём IP клиента из `X-Real-IP`) | `1` | переменная |
| `TELEGRAM_API_BASE` | только для тестов, в бою не задавать | | — |

Защита, которая уже встроена: проверка имени, телефона (российский, 11 цифр), галочки согласия, «ловушка» для ботов (скрытое поле), ограничение длины полей и размера запроса (8 КБ), приём только с вашего домена (CORS), не больше 5 заявок с одного IP за 10 минут. В логах телефон и IP замаскированы, имени нет.

## 3а. Деплой Cloudflare Worker

1. Зарегистрируйтесь на cloudflare.com (бесплатный тариф). На компьютере нужен Node.js 18+.
2. В папке `server/` откройте `wrangler.toml` и в `ALLOWED_ORIGIN` впишите адрес сайта.
3. В терминале, в папке `server/`:
   ```
   npx wrangler login
   npx wrangler secret put BOT_TOKEN      # вставить токен
   npx wrangler secret put CHAT_ID        # вставить chat id
   npx wrangler deploy
   ```
4. Wrangler покажет адрес вида `https://servis-lyuks-leads.<ваш-аккаунт>.workers.dev` — это и есть endpoint.
5. (Необязательно) общий лимит заявок через KV — инструкция в комментарии `wrangler.toml`. Без KV лимит работает «в памяти» и для небольшого сайта его достаточно.
6. Логи: `npx wrangler tail`.

## 3б. Деплой своего сервера в РФ (node-server)

На VPS в российском дата-центре (Ubuntu, Node.js 18+; зависимостей ставить не нужно):

1. Скопируйте папку `server/` на сервер, например в `/opt/servis-leads`.
2. Создайте файл с секретами `/etc/servis-leads.env` (права `600`, владелец root):
   ```
   BOT_TOKEN=...
   CHAT_ID=...
   ALLOWED_ORIGIN=https://servis-lux.ru,https://www.servis-lux.ru
   LEADS_FILE=/var/lib/servis-leads/leads.jsonl
   TRUST_PROXY=1
   ```
3. Сервис systemd `/etc/systemd/system/servis-leads.service`:
   ```
   [Unit]
   Description=Servis-Lux leads
   After=network.target
   [Service]
   EnvironmentFile=/etc/servis-leads.env
   ExecStart=/usr/bin/node /opt/servis-leads/node-server.mjs
   DynamicUser=yes
   StateDirectory=servis-leads
   Restart=always
   [Install]
   WantedBy=multi-user.target
   ```
   `systemctl daemon-reload && systemctl enable --now servis-leads`; логи — `journalctl -u servis-leads -f`.
4. nginx с HTTPS (Let's Encrypt), например на поддомене `api.servis-lux.ru`:
   ```
   location /lead {
     proxy_pass http://127.0.0.1:8787;
     proxy_set_header X-Real-IP $remote_addr;
     client_max_body_size 16k;
   }
   ```
   Endpoint: `https://api.servis-lux.ru/lead`. Проверка живости: `GET /health` → `{"ok":true}`.
5. Файл `leads.jsonl` — это копия всех заявок с персональными данными: доступ только у ответственного лица, регулярно удаляйте старые записи (срок — по Политике конфиденциальности), включите его в резервное копирование.

## 4. Подключить endpoint на сайте

В `js/config.js` (файл прораба) впишите адрес приёмника:
```js
leadEndpoint: 'https://servis-lyuks-leads.<аккаунт>.workers.dev',   // или 'https://api.servis-lux.ru/lead'
```
Пусто → заявки снова пойдут через WhatsApp. Токен бота в `config.js` **не** писать — он только на сервере.

## 5. Яндекс.Метрика: цели

1. Создайте счётчик на metrika.yandex.ru (вебвизор не включайте, пока юрист не одобрит), номер счётчика впишите в `js/config.js` → `yandexMetrikaId`. Метрика загружается **только после согласия** посетителя в cookie-баннере.
2. В счётчике: «Цели» → «Добавить цель» → тип **«JavaScript-событие»**, идентификатор — ровно как в таблице:

| Идентификатор | Когда срабатывает | Важность |
|---|---|---|
| `lead_submit` | заявка успешно отправлена (параметры: `source` — какая форма: hero / modal / contacts, `via` — endpoint или whatsapp) | **главная** |
| `phone_click` | нажали на номер телефона | **главная** |
| `whatsapp_click` | нажали на ссылку WhatsApp | **главная** |
| `lead_modal_open` | открыли окно «Вызвать мастера» | |
| `telegram_click` | нажали на ссылку Telegram (если появится) | |
| `reviews_click` | перешли к отзывам на Яндекс Картах | |
| `map_click` | открыли карту / организацию на Яндекс Картах, 2ГИС | |
| `scroll_25`, `scroll_50`, `scroll_75`, `scroll_100` | долистали страницу до 25/50/75/100 % | |
| `view_services`, `view_brands`, `view_process`, `view_prices`, `view_guarantees`, `view_reviews`, `view_gallery`, `view_faq`, `view_contacts` | посетитель дошёл до раздела | |

   Совет: сделайте составную цель «Контакт» = `lead_submit` или `phone_click` или `whatsapp_click` — это и есть основная конверсия. Для рекламы в Директе отмечайте её как ключевую.
3. Любой элемент сайта можно сделать целью без программиста: атрибут `data-goal="имя_цели"`, затем создать цель с тем же именем.
4. Проверка: откройте сайт с `?_ym_debug=1` в адресе, примите cookie, нажмите на телефон — в консоли браузера (F12) появится `Reach goal … phone_click`.

## 6. Чек-лист боевой проверки

1. [ ] Бот создан, токен сохранён только в секретах сервера (не в коде, не в переписке).
2. [ ] Сначала `CHAT_ID` = ваш **личный** chat id. Приёмник задеплоен, `ALLOWED_ORIGIN` = точный адрес сайта (с `https://`, и вариант с `www`, если он открывается).
3. [ ] `leadEndpoint` прописан, сайт пересобран и выложен.
4. [ ] Отправьте тестовую заявку из **каждой** формы (верх страницы, окно «Вызвать мастера», раздел «Контакты») с телефона и с компьютера. В личку пришло 3 сообщения, на сайте — «Заявка принята!».
5. [ ] Отправка без галочки согласия и с неполным телефоном — сайт не отправляет и подсказывает ошибку.
6. [ ] Имя с символами `<b>` приходит в Telegram как текст, а не жирным.
7. [ ] Поменяйте `CHAT_ID` на **рабочий чат** (Cloudflare: `npx wrangler secret put CHAT_ID`; VPS: правка `/etc/servis-leads.env` + `systemctl restart servis-leads`), повторите одну тестовую заявку — пришла в рабочий чат, менеджеры видят.
8. [ ] Если приёмник «лёг» (выключите его на минуту) — сайт пишет «Не удалось отправить. Позвоните нам или напишите в WhatsApp», заявка не теряется молча.
9. [ ] Метрика: через сутки в отчёте «Конверсии» видны тестовые `lead_submit`, `phone_click`.
10. [ ] Удалите тестовые заявки из чата и из `leads.jsonl`.
11. [ ] Назначьте, кто отвечает на заявки и в какое время; включите уведомления о группе у менеджеров.

## 7. 152-ФЗ — что важно (не юридическая консультация; финально согласовать с юристом)

- Имя и телефон из формы — **персональные данные**. Компания — оператор ПДн: нужна Политика конфиденциальности и согласие (уже есть в `legal/`), и **уведомление в Роскомнадзор** об обработке ПДн (pd.rkn.gov.ru), если оно ещё не подано.
- **Локализация (ст. 18 ч. 5):** запись, накопление и хранение ПДн граждан РФ должны вестись в базах данных на территории России. Поэтому предпочтителен вариант **B** — сервер в российском дата-центре с `LEADS_FILE`: заявка сначала записывается в РФ, затем уведомление уходит в Telegram.
- **Трансграничная передача (ст. 12):** серверы Telegram и Cloudflare находятся за рубежом. Отправка туда имени и телефона — трансграничная передача; о ней нужно отдельно уведомить Роскомнадзор и упомянуть в Политике/согласии. Вариант A (Cloudflare) обрабатывает ПДн целиком за рубежом — использовать только после согласования с юристом.
- Альтернатива без Telegram — уведомление в российский мессенджер/CRM/почту на российских серверах (можно доработать приёмник).
- В логах ПДн нет: телефон маскируется (`+7 *** ***-**-90`), IP обрезается, имя не пишется.
- Храните заявки не дольше, чем нужно (срок — в Политике), доступ к чату и файлу — только у сотрудников, которым это нужно по работе; при увольнении сотрудника удаляйте его из группы.
- Галочка согласия не должна быть отмечена заранее (так и сделано); сервер дополнительно отклоняет заявки без согласия.

## Для разработчика

- Контракт: `POST` JSON `{name, phone, device?, brand?, problem?, consent, source?, page?, website}` → `200 {ok:true}` | `4xx/5xx {ok:false, error}`; коды ошибок: `origin`, `content_type`, `too_large`, `bad_json`, `name`, `phone`, `consent`, `too_long_<поле>`, `rate_limit`, `delivery`, `not_configured`.
- Общая логика — `server/core.mjs`, обёртки — `worker.js` (Cloudflare) и `node-server.mjs` (node:http).
- Тесты: `node server/test.mjs` (поднимает node-server и заглушку Telegram, прогоняет worker).
- Аналитика: `js/analytics.js`, API `window.track(goal, params)`; событие `lead:sent` диспатчит `js/main.js` после успешной отправки.
